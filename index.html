Code Review

Code review is a review process of code by your peers. It is where others review your code to help identify flaws, bugs, edge cases or any other problems that may create issues after the product is released (GitLab, n.d.).

This is an important process because it aids in identifying potential issues that you may not have seen. When I finish an application or an enhancement to an existing application, when I test myself, I know how the process should work. So, it can be difficult to find ways to break my own program. Where others would be able to spot because they are reviewing the code objectively. Without the process, the potential for bad programs to escape increases.

Sensor App

Java
Andoid
Original Project ↗ Enhanced Project ↗
This Artifact is an Android Application that can run on a phone running Android. It is an application that utilizes a phone built in light sensor to display the current ambient light value in Lux (illuminance). It was created to diplay the ability to use the phones internal sensors and functions.
The app displays the current value, the maximum, minimum and average values. I have also included a little "game" where a random lum value gets set and you need to find a place that is within the same brightness. You will get hints on if you are too dark or too bright.
This was initially created In February of 2026

I chose to include this artifact because it displays competence in developing a phone app utilizing build in sensor functions. The use of one sensor gives an understanding of the SensorEventListener and its methods and how they work to create working apps using real time data. Using the data to show the min. max and average displays some practical use of the tools given. The artifact was improved by cleaning errors, adding comments to code blocks that were missing comments and adding functionality on the sensorUpdate method.

The enhancement process allowed me to take more of a design approach since most of the code base was complete. While there were improvements made to the code, the heavier lifting was in the UI/UX. There was a learning curve jumping back into Android Studio. Once I got my bearings, I was able to make the updates and enhancements. The biggest improvement with this app is how the lux is displayed. Giving the user a Max, Min and average brightness. I also added a small game that users can walk around and find the hidden lux value. You get a too high of too low message to help assist in finding that sweet spot.

Enhancement Two: Algorithms and Data Structure

Client Manager

C++
Python
MySQL
Original Project ↗ Enhanced Project ↗

This artifact is a program that maintains client information for an investment company. The program allows users to maintain a set of clients by changing the type of service they are assigned; either Retirement and Brokerage. The original program was created with hard coded uses that only lived during runtime. The username and password were also hard coded in plain text and only lived during runtime. It was designed to as a test to find and correct Software security bugs.
The program was originally created in C++ and created in April of 2026.

Main menu running in a terminal

Creating a user. Password text is hidden from input

User logged in

Password hashed and stored in a database

This was a good candidate because it had the most potential for improvement. It mimics a real-life data and application. Maintaining customer records is always going to be part of almost all industries. This program is a nice framework for maintaining such data. I chose this because I wanted to port from C++ to Python, and this was a nice challenge. I also saw an opportunity to learn and sharpen my skills in password hashing. The original had a hard coded username and password to validate against.

The improvements were more than originally anticipated. The program had five users that were hard coded and the data only lived during runtime. The username had a hardcoded password. My main improvement was to take the runtime and variable users and clients from the code base and create a mySQL database to store and reference client information. The hardcoded username and hashed password were also stored in that database. Another improvement was to port the program from C++ to Python because of the available libraries to handle hashing and cryptography.

Modifying this artifact was a longer process than anticipated. In order to accomplish my goals there were outside resources that needed to be configured. Most notable was the mySQL instance that I had to install and run locally. I learned about using password hashing and the main difference between hashing and encrypting and when to use them. Password and data that you wont need to retrieve would be a candidate for Hashing. Like passwords that only need to be verified by comparing the hashes. Where encryption allows for credentials to be stored safely. One main challenge was to port the program into python and creating classes that help manage each component. Mostly for portability and scaling ease. This would also have been possible in C++, being an OOL.

The specific components that I would showcase is the security improvements of password hashing. Using python libraries to hash a password and to verify a user entry against a hashed password.

The main challenge was figuring out the layout using the .grid() for each component. Once I started to add frames I had a better understanding of how the layouts are.
